# 会话连接接口

更新：2026-10-21（归档）。对应技术方案 v3、PRD v8；实现位于 `server/src/`，共用类型及文字规则位于 `shared/index.ts`。

## 启动和连接

```sh
npm install
npm start
```

服务只监听 `127.0.0.1`，默认端口 4319，占用时依次尝试 4320–4339。以终端或浏览器里的实际地址为准。macOS 应用通过 `npm run app` 生成到 `/Applications/会话连接.app`。前端已完成（`web/src/`），PRD v8 验收全部通过（2026-10-21）。

- 支持的 Node 范围：20.19.x 及其后续 20.x、22.12.x 及其后续 22.x，或 ≥24；本次实测为 macOS 26.6.2 / Node 25.7.0。
- `npm run dev` 同时启动 Vite 与后端 watch；Vite 代理从当前数据目录的 `instance.lock` 跟随实际端口。开始开发前先退出已运行的应用或服务。
- 默认数据目录：`~/.session-connect/`。隔离测试可设置 `SESSION_CONNECT_HOME=/绝对路径`；应用和终端进程使用同一个目录时共用单实例锁。
- 不开 CORS。Host 必须为 `127.0.0.1:<实际端口>` 或 `localhost:<实际端口>`。有 Origin 时，必须与 Host 对应的 HTTP 源完全一致。
- JSON 请求用 `Content-Type: application/json`；没有请求体时省略 Content-Type。上传图标另用原始图片字节和对应图片 MIME。

## 数据类型

以下字段名与 `shared/index.ts` 一致：

| 类型 | 字段 |
| --- | --- |
| Canvas | `id, name, createdAt, revision, lastSaveId, viewport, cards, edges` |
| Card | `id, x, y, iconId, name, note, status` |
| Edge | `id, a, b, direction, label` |
| Viewport | `{x, y, zoom}`，坐标为有限数，zoom 为 0.1–2 |
| Icon | `{id, builtin, mime, hash, url}`；hash 为原始字节的 SHA-256 |
| Prefs | `{lastCanvasId: string \| null, minimapVisible: boolean}` |
| ImportResult | `{canvasIds: string[], iconsAdded: number}` |
| Notice | `null` 或 `{kind: "restored" \| "reset", backupTime?, brokenPath}` |

- `status`：`todo / doing / done / blocked`。
- `direction`：`forward`（a→b）、`backward`（a←b）、`both`。
- 内置图标：`claude-code / codex / deepseek / workbuddy`。
- `revision` 初始为 0，`lastSaveId` 初始为 null；只保存画布内容才增加 revision。
- 文字使用共用 `normalizeText` 去首尾空白、把换行替换为空格，再按 `Intl.Segmenter` 字素计数。画布名 1–30 字、卡片名 1–40 字、备注 0–60 字、连线文字 0–20 字。
- 卡片与连线 id 在同一画布内不能重复；连线端点必须是两张不同的现有卡片，同一无序卡片对最多一条连线。卡片数和画布数不另设上限。

## 接口列表

| 方法和路径 | 请求 | 成功响应 |
| --- | --- | --- |
| `GET /api/health` | 无 | 200 `{app:"session-connect",version,pid,port}` |
| `GET /api/state` | 无 | 200 `{schemaVersion:1,canvases,icons,prefs,notice}` |
| `POST /api/notice/ack` | 无 | 204；本次运行不再返回 notice |
| `GET /api/canvases/meta` | 无 | 200 `[{id,name,revision}]`，数组顺序为画布顺序 |
| `POST /api/canvases` | `{id,name}`，id 为前端生成的 UUID | 201 Canvas；id 已存在则 200 返回已有 Canvas，不覆盖内容 |
| `PATCH /api/canvases/:id` | `{name}` | 200 `{id,name}`；不改 revision |
| `DELETE /api/canvases/:id` | 无 | 204；不存在时也返回 204 |
| `PUT /api/canvases/:id/content` | `{baseRevision,saveId,cards,edges}` | 200 `{revision}`；保存及重试规则见下文 |
| `PUT /api/canvases/:id/viewport` | `{x,y,zoom}` | 204；不改 revision，后写为准 |
| `PUT /api/prefs` | `{lastCanvasId?,minimapVisible?}` | 204；只更新传入字段，lastCanvasId 可为 null |
| `POST /api/icons` | 原始字节，MIME 为 `image/png / image/jpeg / image/webp / image/svg+xml` | 201 Icon；相同字节已存在时 200 返回已有 Icon |
| `DELETE /api/icons/:id` | 无 | 204；不存在时也返回 204；内置图标不可删 |
| `GET /icons/:id` | 无 | 200 原始图片字节 |
| `GET /api/export` | 无 | 200 JSON 附件，格式见下文 |
| `POST /api/import` | 导出文件的 JSON；头 `X-Import-Id: <UUID>` | 200 ImportResult |
| `GET /api/imports/:importId` | 无 | 200 ImportResult；202 `{code:"IMPORT_IN_PROGRESS",message}` |
| `POST /api/imports/:importId/ack` | 无 | 204；不存在或已确认也返回 204 |

删除画布时，若它是持久化的 `lastCanvasId`，服务将其设置为第一张剩余画布，或 null；前端按 PRD 选择上方画布后，可再保存自己的当前画布偏好。删除图标不修改卡片的 iconId 或 revision；前端找不到图标时显示 Claude Code 图标。

## 保存与重试

```http
PUT /api/canvases/4feb2fb4-7a95-4e50-8d98-7c389637f36f/content
Content-Type: application/json

{"baseRevision":0,"saveId":"7d6949fe-20a0-4504-9589-c2ee2a2c9e76","cards":[],"edges":[]}
```

首次成功返回 `200 {"revision":1}`。只有 `baseRevision` 等于当前 revision 才写入，并同时持久化 revision+1 和 lastSaveId。

若 `baseRevision` 为当前 revision−1，且 saveId 等于持久化的 lastSaveId，直接返回当前 revision；同一请求重试和服务重启后重试都不重复写盘。其余版本不匹配返回：

```json
{"code":"REVISION_CONFLICT","message":"这张画布在别的标签页改过了","revision":1}
```

状态为 409。画布已经删除时返回 404 `CANVAS_NOT_FOUND`。没有收到明确响应时，前端必须保留原 baseRevision、saveId 和内容重试，不能用新内容冒充上一个请求。

## 图标

上传上限为 1 MiB（1,048,576 字节）。四种图片共享同一校验：声明类型匹配、sharp 完整解码；SVG 根必须为 svg，并完成一次解析渲染。仅文件头可读的截断图片也会失败。

```sh
curl --data-binary @/绝对路径/icon.png \
  -H 'Content-Type: image/png' \
  http://127.0.0.1:4319/api/icons
```

返回的 url 可直接作为 img src。图片响应包含：

```text
X-Content-Type-Options: nosniff
Content-Security-Policy: default-src 'none'; style-src 'unsafe-inline'
```

重复上传按原始字节 hash 去重；删除后重传会生成新 id，不会让使用旧 id 的卡片重新关联它。

## 导出与导入

导出文件以 `{"format":"session-connect-export"` 开头，第一个字段固定为 format：

```text
{format:"session-connect-export",formatVersion:1,exportedAt,canvases,
 icons:[{id,mime,hash,dataBase64}]}
```

附件名通过 `filename*=UTF-8''...` 返回，解码后为 `会话连接-备份-YYYYMMDD-HHmm.json`。导出包含全部可用的上传图标字节，不包含偏好设置和导入历史。图标文件读不到、超过单图标大小上限或 hash 不符时，跳过该图标并记录 `icon_unavailable`，画布、卡片和连线继续导出，当前 data.json 不因此改变；保留的 iconId 找不到图标时按既有前端规则显示 Claude Code 图标。导入文件自身含有损坏图标仍整体拒绝。

一般请求体配置上限仍为 1 GiB（1,073,741,824 字节），不做分卷。**当前整串 JSON 实现尚不能完整支持此上限**：V8 单字符串上限会使更小的文件在导出或导入中失败，直接发送大 JSON 还可能令服务退出；前端 file.text() 也有同类限制。详见技术方案后端审核 R1-3 遗留，本轮未降低接口约定上限。

```sh
curl -o /tmp/会话连接-导出.json http://127.0.0.1:4319/api/export
curl --data-binary @/tmp/会话连接-导出.json \
  -H 'Content-Type: application/json' \
  -H 'X-Import-Id: 51a3d89a-c50e-49f6-b3d3-fd9a6bb405c3' \
  http://127.0.0.1:4319/api/import
```

- 导入前完整校验结构和每个图标，失败不改变 data.json 或 icons 目录。
- 新画布追加到末尾；画布、卡片、连线生成新 id，保留名称、位置和内容；新画布 revision=0、lastSaveId=null。图标按 hash 去重并重新映射。
- 内容与未确认导入记录在同一次原子写入提交。同一 importId 重复提交返回同一结果，重启仍有效；在途重复提交等待首个请求完成。
- 从收到请求头开始登记进行中，早于读取 JSON 请求体；查询处理中为 202。成功为 200；没有提交且没有处理中的请求为 404。
- 收到 200 或查询核对为 200 后调用 ack。未确认记录永不清理；已确认的保留最近 20 条，可能查到 404。
- 断线后先查询，不能自动再次导入；202 继续查、200 按成功处理并 ack、404 才能提示未完成。前端不为导入设超时。

## 错误响应

错误统一为 `{code,message}`，必要时增加 reason、detail 或 revision。前端按 code 使用 PRD 文案。

| HTTP | code | 说明 |
| --- | --- | --- |
| 400 | `INVALID_NAME` | 画布名称为空或超过 30 字 |
| 400 | `INVALID_CONTENT` | 文字、id、枚举、坐标、端点等不合法；detail 给出校验原因 |
| 400 | `BUILTIN_ICON` | 尝试删除内置图标 |
| 400 | `INVALID_FILE` | 非本程序文件、损坏 JSON、结构或任意图标不合法；没有导入内容 |
| 400 | `NEWER_VERSION` | formatVersion 高于当前版本 |
| 400 | `MISSING_IMPORT_ID` | 缺失或无效的 X-Import-Id |
| 403 | `FORBIDDEN` | Host 或 Origin 不允许 |
| 404 | `CANVAS_NOT_FOUND` | 画布不存在 |
| 404 | `ICON_NOT_FOUND` | 图标或图标文件不存在 |
| 404 | `IMPORT_NOT_FOUND` | 没有这次已提交或处理中的导入 |
| 409 | `REVISION_CONFLICT` | 版本冲突；revision 为当前版本 |
| 413 | `TOO_LARGE` | 上传图片超过 1 MiB，或其他请求超过 1 GiB |
| 415 | `UNSUPPORTED_TYPE` | 上传不是四种支持的 MIME |
| 422 | `UNREADABLE` | 图片无法完整解码或声明 MIME 不匹配 |
| 500 | `WRITE_FAILED` | 写盘失败；reason 为 `disk_full / no_permission / other` |
| 500 | `INTERNAL_ERROR` | 其他服务错误 |

`WRITE_FAILED` 表示事务未提交，内存也未切换到新状态。即使磁盘满导致日志也写不进去，仍返回原始写盘错误。新增图标在 data.json 提交失败时清理；崩溃遗留的孤儿图标于下次启动清理。

启动备份失败只记 `backup_failed`，已有数据仍可使用。data.json 损坏而恢复或重置时，原文件保留为 notice.brokenPath，非空的原 `icons/` 同时保留为 `<brokenPath 去掉 .json>-图标/`；这些恢复材料不会被后续孤儿清理删除。工作用 icons 目录重新建立，再从备份逐个恢复通过校验的图标；某个图标损坏不作废整份画布备份。
