## 改动概述

- 涉及项目：session-connect（本地服务 + 网页，同一个仓库）。
- 涉及模块：`shared/`（类型和常量）、`server/src/validation.ts`（内容校验）、`web/src/logic/edges.ts`、`web/src/store.ts`、`web/src/components/Board.tsx`、`web/src/components/Panel.tsx`、`web/src/styles.css`（如需）。
- 数据变更：连线 `Edge` 增加一个字段 `activity`，取值 `'follow'`（跟随卡片）/ `'off'`（不活跃）。
  - data.json、备份、导出文件里的连线变成 `{ id, a, b, direction, label, activity }`。
  - `schemaVersion` 仍为 1，导出 `formatVersion` 仍为 1，不做迁移步骤。
  - 读取时缺少 `activity` → 当作 `'follow'`；有这个字段但值不在两个取值里 → 校验失败。
- 现状证据：
  - 现在的流动规则只有一行：`web/src/components/Board.tsx:72` `flowing = doing.has(edge.a) || doing.has(edge.b)`。线和箭头的颜色、`FloatingEdge` 里的 `flowing` 类名都由它决定（`Board.tsx:76`、`FloatingEdge.tsx:30`）。
  - 服务端所有读入连线的路径都经过同一个函数 `content()`（`server/src/validation.ts:42`），它按字段重建对象、丢弃不认识的字段（第 73 行）：
    - `PUT /api/canvases/:id/content`（`server/src/app.ts:103`）；
    - 启动时读取 data.json、用备份恢复（`server/src/store.ts:107`、`:159`，经 `dataFile()` → `canvas()` → `content()`）；
    - 导入（`server/src/transfers.ts:128`，经 `canvas()`）。导入时连线用 `{ ...e, id, a, b }` 重建（`transfers.ts:91`），校验后的字段会原样带上。
  - 导出直接输出内存里的 `data.canvases`（`transfers.ts:62`），内存里的数据都是 `dataFile()` 校验过的。
  - 前端建新连线只有一处：`web/src/logic/edges.ts:27`；合并成双向用 `{ ...existing, direction: 'both' }`（`edges.ts:31`），其他字段原样保留；`sanitized()`（`store.ts:121`）用展开语法，也会带上新字段。
  - 复制卡片不复制连线（`store.ts:498`）。
  - `edit()` 在内容没变时返回 `false`，不记撤销步骤（`store.ts:438`）；`setEdgeDirection` 就是靠它做到"点当前方向不产生步骤"（`store.ts:628`）。
  - 前端导入预检 `analyzeImport()`（`web/src/logic/importFile.ts`）只统计画布数和图标数，不检查连线字段；连线字段非法由服务端返回 `INVALID_FILE`，前端已经显示为"文件格式不对，没有导入任何内容"。
- 关键流程：
  1. 服务启动：`dataFile()` 读 data.json，缺少 `activity` 的连线在内存里补成 `'follow'`。`GET /api/state` 返回的每条连线都带 `activity`。
  2. 用户在连线面板点「不活跃」→ 前端 `setEdgeActivity` 改本地内容、记一步撤销 → 和其他改动一样自动保存，`PUT content` 带上 `activity`。
  3. 画面：`Board.tsx` 计算 `flowing` 时多判断一条：`activity === 'off'` 时恒为 `false`。
  4. 导出原样带出；导入时经 `content()` 校验，缺字段补 `'follow'`，非法值整个文件拒绝。

## 不做什么

- 不做 PRD"本期不做"里的内容：第三档"总是活跃"、右键菜单 / 卡片面板入口、不活跃的特殊样式、批量设置。
- 不提升 `schemaVersion` / `formatVersion`，不写启动时的迁移代码，也不在启动时为了补字段而主动重写 data.json（下次正常保存这张画布时自然写入）。
- 不改 `fixtures/perf-200.json` 和 `scripts/make-perf-fixture.mjs`：现有夹具没有 `activity`，正好用来验"旧文件导入"（PRD B1）。
- 不改接口路径、请求结构以外的任何东西；`docs/接口.md` 在归档时再同步（Edge 字段表、`activity` 取值说明）。

## 风险

- 回退到旧版本时活跃设置丢失：PRD 已写进已知限制，不处理。
- 升级时页面还开着（旧前端代码，新服务）：旧前端拿到的连线带 `activity`，它的建线、合并、保存都用展开语法，会原样带回去；旧前端新建的线没有这个字段，服务端按 `'follow'` 处理。所以 PUT 时缺字段必须接受，不能报 400。**这一点是推断，没有实测**；用户刷新页面后就是新代码。
- 性能：`flowing` 多一次字段判断，没有新增渲染；`Board.tsx` 的连线缓存比较的是 `prev.data.edge === edge`，`activity` 变化时连线对象会换新，缓存自然失效，不用改缓存逻辑。

## 接口约定

无新接口，路径和错误码都不变。只是连线对象多了一个字段，影响以下接口的连线结构：

- `GET /api/state`：返回的每条连线一定带 `activity`。
- `PUT /api/canvases/:id/content`：请求里的连线 `activity` 可以省略（按 `'follow'`）；值不合法 → 400 `INVALID_CONTENT`（前端只发合法值，正常不会出现）。
- `GET /api/export`：每条连线带 `activity`。
- `POST /api/import`：连线 `activity` 可以省略（按 `'follow'`）；值不合法 → 400 `INVALID_FILE`，前端提示"文件格式不对，没有导入任何内容"（现有映射，不改）。

示例：

```json
{ "id": "e1", "a": "c1", "b": "c2", "direction": "forward", "label": "", "activity": "off" }
```

#### 实际请求/返回示例

以下来自构建后 `node dist/server/index.js --mode dev` 的隔离服务，通过真实 HTTP 请求验证。

1. 保存不活跃连线：`PUT /api/canvases/11111111-1111-4111-8111-111111111111/content`，`Content-Type: application/json`：

```json
{
  "baseRevision": 0,
  "saveId": "activity-off-1",
  "cards": [
    { "id": "c1", "x": 0, "y": 0, "iconId": "codex", "name": "A", "note": "", "status": "doing" },
    { "id": "c2", "x": 240, "y": 0, "iconId": "codex", "name": "B", "note": "", "status": "todo" }
  ],
  "edges": [
    { "id": "e1", "a": "c1", "b": "c2", "direction": "forward", "label": "", "activity": "off" }
  ]
}
```

返回 HTTP 200：`{ "revision": 1 }`。`GET /api/state` 返回节选（省略其他字段）：

```json
{
  "schemaVersion": 1,
  "canvases": [{
    "id": "11111111-1111-4111-8111-111111111111",
    "revision": 1,
    "edges": [{ "id": "e1", "a": "c1", "b": "c2", "direction": "forward", "label": "", "activity": "off" }]
  }]
}
```

2. `GET /api/export` 返回 HTTP 200，`format` 为 `session-connect-export`、`formatVersion` 为 1，对应连线与上例一致，`activity` 为 `'off'`。把这份完整响应作为 `POST /api/import` 的请求体，头 `x-import-id` 使用新 UUID，实际返回 HTTP 200：

```json
{ "canvasIds": ["6437bc5a-894b-4cf4-890a-c87342c5c48e"], "iconsAdded": 0 }
```

读回导入的画布，连线的 `activity` 仍为 `'off'`，画布、卡片和连线 id 按既有规则重新生成。

3. 同一保存请求改为 `baseRevision: 1`、`saveId: "activity-invalid-1"`、`activity: null`，实际返回 HTTP 400：

```json
{ "code": "INVALID_CONTENT", "message": "内容不合法", "detail": "连线活跃设置不合法" }
```

把上述导出文件的连线改为 `activity: "on"` 后导入，实际返回 HTTP 400：

```json
{ "code": "INVALID_FILE", "message": "文件格式不对，没有导入任何内容" }
```

这两次失败后，`data.json` 字节及 `GET /api/state` 均与请求前一致。

4. 上述保存请求省略连线的 `activity`，使用 `baseRevision: 1`、`saveId: "activity-legacy-1"`，返回 HTTP 200 `{ "revision": 2 }`，读回为 `'follow'`。临时生成的旧格式性能夹具也通过真实 HTTP 导入，200 张卡片、300 条连线全部保留，所有连线均补为 `'follow'`。
